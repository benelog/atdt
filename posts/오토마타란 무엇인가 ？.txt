오토마타란 무엇인가 ?                        11/25 04:40   454 line


   안녕하십니까. 한 재룡입니다.

   한글 입력 오토마타에 대한 대강입니다. 예제는 없읍니다. 한글 입력
   오토마타 에 대한 예제를 짜려면 한글에 대한 입/출력이 모두 지원되
   야하기 때문에 결국엔 한글 라이브러리가 되어버릴 것 입니다. 하지만
   한글 입력 오토마타의 본체와 자세한 설명을 드리겠읍니다.

   여기서는 오토마타의 종류와 그 차이점, 그리고 한글 입력의 특성과
   문제점등을 살펴보겠읍니다. '마이크로 소프트' 과월호가 있으면
   실제로 한글 입력에 사용되는 오토마타의 예제를 구할 수 있나 보던데.

   여러분 중에 아직 오토마타가 무슨 뜻이고 그 알고리듬에는 어떤 것이
   있는가를 모르시는 분이나 현재 소스로 공개되어 '피박' 과 '개털' 에
   올라있는 코드가 전혀 마음에 오지 않는 분들께는 좋은 읽을거리가
   되리라고 믿읍니다.

   이 두 화일은 다음과 같이 구성이 되겠읍니다.

    1. 오토마타란 ??
    2. 오토마타의 종류
    3. 한글 입력의 특성
    4. DFA 를 이용한 한글 입력 오토마타의 작성

1. 오토마타란 ??

    컴퓨터에서 이루어지는 모든 명령의 흐름은 '분기' 에 의하여 선택된
    명령어만을 실행함으로써 이루어지게 됩니다. 흔히 사용되는 if, while
    for 문이 하이레벨 랭귀지에서 사용되는 명령어 부럭의 구조를 분기시
    키는 역활을 하게됩니다. 이중에 특히 입력되는 데이터의 종류를 구별
    하여 명령문을 선택 실행하는 것은 if 와 case 문이 됩니다. 만일 데이
    터의 '참'과 '거짓' 만이 중요 할 때는 if 문이 사용되어  Boolean
    expression 에 대한 분기문으로 사용되고 또 입력 데이터의 형이 항상
    일정하고 그 경우의 가지수가 일정하다면 case 문을 사용하여 각각의
    명령어 부럭을 선텍 수행케 합니다. 그런데 만일 경우의 가지의 수가
    너무 크거나 또는 스트링( 연속입력 )형테의 입력이 이루어져 항상
    이전에 입력된 '값'이 그 다음에 오는 데이터의 처리에 중대한 영향을
    미치며 이 '상태'가 누적되어가는 데이터의 처리는 if 와 case 문 만으
    로는 프로그램의 정상적인 흐름을 제어하기가 어렵게 됩니다.

    위와 같은 경우는 흔히 있읍니다. 흔히 사용되는 예로서 만일 씨에서
    int 와 float 변수를 구별하는 경우를 예를 든다면

        11188       ----> int
        .111        ----> float
        11188.      ----> 오류
        11.889      ----> float
        11E.00      ----> 오류
        1100.0E     ----> 오류
        1111.00E1   ----> float

    와 같은 대체적인 경우의 가지수가 있게 됩니다. 입력 데이터의 종류
    는 한 가지로서 일반 아스키 문자열이고 이 문자열에서 두 가지의
    변수 형테가 리턴되게됩니다.
    이와 같이 한정된 경우의 수( 5의(자리수)승 )와 한정된 데이터의
    입출력을 하나의 분리된 함수들에서 처리를 하게된다면 그 함수들을
    오토마타라고부르게 됩니다. 위의 예를 if 와 case 문만으로 작성할있
    다는 것은 확실합니다.
    그러나 아마도 쓰는 시간의 수십배에 달하는 디버깅시간이 요구되고 또
    약간의 입출력 형태의 변화가 오면 코드를 유지하는 데에 상당한 출혈
    을 요구당하게되고, 읽기가 어려운 코드가 되며 속도에서도 큰 손실이
    오고 주 함수의 크기가 상당히 커지게 되어 중복된 코드가 생길 가능성
    이 크게 됩니다. 하지만 오토마타를 스스로 작성할 수 없는 분에게는
    선택의 여지가 없겠지요.

    오토마타가 가장 많이 사용되는 곳은 일반적으로 '스트링'을 다루는 곳
    이고 에디터에서 Unix Regular Expression, 스펠체커, 화일의 데이터
    필드 옮기기 와 랭귀지 컴파일러 등이고 그 중에서  하드웨어의 콘트롤
    러분야에서
    특히 많이 사용되나봅니다. 한글의 입력도 오토마타에 의한 처리가 적
    당하지만 제가 본 소스중에는 '오토마타' 라고 불리울만한 것은 아직
    본적이 없는 것같고 '오토마타'에 사용하는 'Finite State' 배열을 사용

    한 프로그램이 있었는데 지금 찾아보니 없어졌군요. 하지만 완성된 모듈

    은 아니였죠.
    어쩌면 한글 입력은 사실 정확하게 입력 데이터를 '초', '중', '종' 의
    3 가지로 구분할 수 있기때문에 시간을 들여 '오토마타'를 작성할 필요
    가 없을는지도 모릅니다.

2. 오토마타의 종류

    이 부분에 관한 정확한 정의는 아직 없는 것 같읍니다

    만일 입력된 스트링이 정수인지 아닌지만을 검사하는 함수가 있다면
    하나의 함수로서 작성이 가능하게 되는데 이는 입력 데이터의 경우가
    2 가지로서 '숫자' 와 '숫자아님' 의 Boolean 형으로 구분이 되기 때문
    입니다.
    이 Boolean 형도 분명히 오토마타에 범주에 드는 것임에는 틀림이 없으
    나 실제적으로 간단히 while == if 문으로 작성되는 함수를 오토마타라
    고 부르지는 않읍니다. Boolean 형의 오토마타가 컴퓨터에 사용된 것이
    1930 년대인 것으로 알고 있읍니다만 그때에도 '오토마타' 라는 신조어
    가 있었는지는 확실하지 않읍니다.

        가. Finite automaton |-- DFA (Determinstic Finite Automata)
                             |-- NFA (Nondeterminstic Finite Automata)

        나. Finite State Transducers
        다. Pushdown Automata
        라. Turing Machines

  가. Finite automaton

    흔히들 이 '오토마타' 를 '인식기 (Recongnizer)' 라고 부르며 위에
    예를 든 정수 와 실수를 구별하는 것과 같은 한정된 경우의 가지수가
    연속된 입력에 적용되는 오토마타입니다. 다시말해서 위의 예에서는
    입력의 가지수가

        [-+] [ 0..9 ], [.], [eE] 과 '해당 안됨'

    등 5 가지로 나눌 수가 있으며 이 입력의 가지의 수가 계속해서 입력
    되는 한 문자에 적용이 됩니다. 이 입력된 문자는 각각의 상황에 따라서

    단계별로 구분이 가능한데 이 단계를 간단히 예를 들자면

        시작    -->   Sign(+, -)
        Sign    --> : Digit                         State   0
                    : '.'
                    : #

        Digit   --> : Digit                         State   1
                    : '.'
                    : EOS           ====> 정수
                    : #

        '.'     --> : Digit@                        State   2
                    : 'e', 'E'
                    : #

        'e','E' --> : Digit@@                       State   3
                    : #

        Digit@  --> : Digit@                        State   4
                    : 'e', 'E'
                    : EOS           ====> 실수
                    : #

        Digit@@ --> : Digit@@                       State   5
                    : EOS           ====> 실수
                    : #

    과 같읍니다. 이 관계를 그림으로 그리고 싶지만 택스트 모드에서 한계
    가 있어서 그냥 설명하겠읍니다. 위의 예는 각 단계별로 나누고, 그
    단계에서 입력 받는 종류와 그 입력에 따른 다른 단계로의 이동, 그리고

    EOS(End Of String )으로 표시된 '인식(받아드림)' 할 수 있는 단계들,
    또 '#' 표시된 '오류' 로서 정수도 실수도 아님을 나타냅니다.

    예로서 '3.0E4' 라는 입력이 있다면 처음 '시작' 을 한다음에 'Sign'
    에서 '3' 에 해당하는 'Digit' ( State 1 ) 로 가게되고, '.' 에 해당
    하는 경로를 따라서 '.'(State 2) 로가고 계속해서 'Digit@@'(State 5)
    로 간다음 에 EOS 가 되어 실수를 리턴하게 됩니다. 만일 '2.' 이라는
    입력이라면 '.'( State 2 ) 에서 EOS 가 입력되지만 해당하는 경로가
    없으므로 '오류'를 리턴하게 됩니다. 물론 만일 한글이라면 '오류' 가
    아니라 '한 문자 끝'을 리턴해야 하겠지만 위의 예는 컴파일러등에서
    사용되는 Token Recongnizer 입니다. 그럼 위의 '오토마타' 를 알기슆
게
    배열을 한다면 다음과 같읍니다.

         단계  |   '.'   '0'-'9'   'E'  |  EOS 때의 '인식'
        ===================================================
           0   |    3       1       -   |    #
           1   |    2       1       3   |   정수
           2   |    -       2       3   |    #
           3   |    -       4       -   |    #
           4   |    -       4       -   |   실수
           5   |    -       5       -   |   실수

    처음 시작은 0 단계에서 시작을 하게되고 여기서 'E' 가 들어오게 되면
    # 가 됩니다. 만일 '숫자' 이면 1 단계로 가게되고 '.' 이면 3 단계로
    가면 이밖의 입력은 # 입니다. 위와 같이 테이블로 구성된 것을 Finite
    State Machine 이라고 부릅니다. 이 테이블은

        while ( (state = Table[state][input]) != - )
        {
                ...
                input = getInput();
                if( input == EOS )
                    return AcceptTable[state];
        }
        return #;

    과 같이 이용됩니다. AcceptTable 은 그 단계에서의 '인식'을 가진
    테이블 입니다.

    위와 같이 한정된 단계 테이블로 작성할 수 있는 것을 Finite Automata
    라고 부르며 여기에는 DFA 와 NFA 가 있읍니다.

    A. DFA ( Determinstic Finite Automata )

        각 단계를 정형화할 수 있고 그 단계가 항상 일정하다면 그 단계
        들을 Finite State Machin 으로 만들어 쓰는 방식입니다. 한글의
        입력도 각 단계를 정형화할 수 있으며 가장 간단한 형태의 오토마타

        인 DFA 로 작성할 수 있읍니다. 2 벌식 과 3 벌식은 테이블만
        바꾸어 사용할 수 있을 것입니다.

    B. NFA or NDFA ( Nondeterminstic Finite Automata )

        이 방식은 동적으로 여러개의 DFA 를 만들어서 그 DFA 들을 유기적
        으로 연결하여 사용하는 방식으로 한 단문을 인식하는 데에 주로
        사용됩니다.

        DFA 는 한 단어를 인식하는 데 사용된다면 NFA 는 예를 들어서

           _Address_Of_6845++==_Color_Port|4;

        이라는 문구절은 씨 프로그램에서 어디에서나 문장을 구성하는 구
        로서 등장을 하게 되는데 이 문장이 적법한가를 따지려면 우선은
        변수가 씨에 적법한 변수형을 가지고 있는 가를 알아내는 DFA 와
        '연산자' 가 적법한 가를 알아내는 DFA 가 필요하며 끝으로 이 DFA
        등의 연결이 올바른
        가를 알아내는 DFA 가 필요하게 됩니다. 위의 문장은 '==' 부분이
        틀려있으며 씨 컴파일러는 정확히 그 부분을 찾아낼 것이며 한 화일

        을 컴파일하는데에는 이 보다도 훨씬 더 복잡한 여러 '오토마타'가
        수도없이 불리우게 될 것 입니다.

        NFA 의 가장 흔한 예는 Unix 의 유틸리티 grep 에서 볼 수 있읍니다

        도스에도 'grep like' 한 프로그램들이 많이 있고, 터보씨등에는
        자체에 내장되어있어 'Regular Expression'이란 옵션을 준비하고
        있읍니다. 하지만 거의 전부가 DFA 나 if == case 문으로 작성되어
        있읍니다. 그것을 간단히 아는 방법은 'grep like' 한 프로그램에
        'OR Expressin'이 있는 가를 보면 알게됩니다. 'OR Expression' 은
        최소 두개의 DFA 가 연결되지 않으면 사실 구현이 안됩니다. 보통
        Unix grep 에서 사용되는 'OR Expression' 은 '|' 과 '?' 이 있읍
        니다. 앞에것은 씨의 오퍼레이터와 비슷하며 뒤의 '?' 는 '맞는
        것이 하나만있거나 없거나' 입니다. 도스에서의 '?*' 등과는 그
        의미가 틀립니다. 제가 가진 Xenix 의 'grep' 역시'OR Expression'
        을 지원하지 않읍니다. 책에 있는 소스를 컴파일 하니까 80 Kb 를
        상회하더군요. 배열을 선언한 것을 감안하더라도 OR Expression
        없이 하면 15 Kb 정도로서 300-400 라인이면 되는것을 생각한다면
        상당한 차이입니다. PDS 랭귀지 코너에 있는 grep 은 상당히 특이한

        방식을 사용했더군요. 두 가지가 있던데 한 사람이 버전 업한것
        입니다. '오토마타'와 if == case 문의 중간 쯤되는 형태인데
        상당히 빠르게 돌아갑니다.

나. Finite-State Transducers

    이 오토마타는 위의 NFA 에서 나온 각 스트링의 결과 전체를 묶는
    역활을 합니다. 그러니까

        if( state = Table[state][input], state != '-' ) {

    과 같은 한 복문( 여러개의 NFA 의 결합 )을 실재 프로그램 내부에서
    사용하는 'Sequential Machine'( transducer ) 로 바꾸는 '오토마타'
    입니다. 이 오토마타는 하드웨어의 ROM 에 넣고 사용하는 예는 아마
    'Vending Machine'(무인판매기) 등에 사용되는 것 같고, 소프트 웨어
     로서는 컴파일러와 스펠체커등이 있겠읍니다.

    그림으로 이 오토마타가 하는 일을 보면   a - b - c 로 예를 들자면

                       ---- < 문장 >
                      /        |    \
                    /          |      \
                < 문장 >       |    < 변수 >
              /    |  \        |       |
            /      |    \      |       |
        <변수>     |    <문장> |       |
          |        |      |    |       |
          |        |    <변수> |       |
          |        |      |    |       |
          a        -      b    -       c

    가 됩니다. 위의 예에서 '문장' 은 단지

        문장 시작 ===>    문장 : 연산자 : 변수

    의 형태이고 '문장' 안에서 되부름이 일어납니다. 씨의 간단하다는
    if 문을 보면

        if 시작 : '(' : 문구 : ',' : Boolean : ')' : ';'
                                                   : '{'
                                                   : 문장
                                                   : #
                      : Boolean : ')' : ';'
                                      : '{'
                                      : 문장
                                      : #

    라고 생각할 수가 있고 'Boolean' 이라는 NFA 가 역시 정의되어 있어야
    할 것 입니다.
    이 오토마타는 'Parser'라고 부르기도하며 일반적으로 간단한 계산기
    등에 사용되는 알고리듬이기도 합니다. 이 '오토마타' 는 'Recognizer
    (인식기)'를 수시로 불러서 계층적으로 설계한 되부름 함수들을 이용
    하여 결과를 도출해 냅니다. '인식기'는 NFA 나 DFA 가 되고 간단한
    계산기에서는 'Finite State' 테이블이 없이 '숫자', '변수', '연산자'
    등 만을 리턴하는 getToken() 과 같은 함수 하나로서 해결이 됩니다.

다. Pushdown Automata

    이 오토마타는 위의 'Finite-States Transducers' 와는 달리 '테이블
    운영' 방식의 'Parser'로서 되부름에서 발생되는 '하위함수 호출관계
    유지 불가능'의 문제를 해결할 수 있읍니다. 되부름에서는 주 함수의
    잘 정의된 여러가지 기능이 하위함수에 다시 사용되거나 영향을 미칠
    수가 없게 되는데 만일 문장들이 복잡하여 되부름으로는 전체 프로그램
    을 관리할 수 없게된다면 이 '오토마타' 가 그 문제를 해결하게 됩니다
    또 속도도 훨씬 빨라지게 됩니다. 그 알고리듬 자체는 오히려 되부름
    보다 간단하다고 할 수도 있읍니다.

    이름에서 말하듯이 이 오토마타는 'Top-down' 방식입니다. 'Bottom-Up'
    방식보다는 좀 거친면도 있읍니다. 이 방식은 일단 그 문장이 적법하다
    고 생각된 시점에서, 즉 한번의 패스를 거치던지 아니면 '적법한 문장'
    이라는 가정을 한 상태에서 시작하게 됩니다. 한 문구가 시작될 때에
    현재의 상태를 스택에 넣고 그 문구의 끝에서 스택으로 부터 '팦' 하게

    됩니다. 이 관계를 간단히 보자면

        단계 |  '('   ')'    ';'  if     변수
        =========================================
          0  | push  error error  push   push  <-- 문장의 첫 시작
          1  : push  pop   error  error  push  <-- 문구의 시작
          2    ...   ...   ...    ...    ...   <-- Boolean 의 시작 등

    등과 같고 '팦' 한 결과가 예상과 틀리다면 '에러'가 나게 되는데 에러

    복구가 거의 불가능하답니다.

    이 방식은 '파스칼' 컴파일러에 사용된 방식으로 알려져있고, 그래서
    인지 파스칼에서는 '해결되지 않은 변수의 조회'와 같은 경우에도 당장
    컴파일을 멈춰버립니다. 그리고 프로그램의 서두에

       function anyFunc : Boolean;

    이라고 써놓고 그 실행부분을 적지않았을 경우에는 전체프로그램을 다
    읽어드린 이후에도 anyFunc 에서 일어난 문제를 알지 못 합니다. 전체
    프로그램이 anyFunc 의 서브 프로시져( 함수나 프로시져가 그 정의
    안에 다른 함수나 프로시져를 가질 수있고 이들은 밖에서는 보이지
    않는다 )로 알아버리게 됩니다. 그리고 전체 프로그램이 하나의 프로
    시져로 간주가 됩니다. 그림으로보면

        program AnyProgram;
        var
            function anyFunc : Boolean;
            var
                function anySubFunc : Boolean;
                var
                    function subSubFunc : Boolean;
                    var
                    begin
                    ...
                    end
                begin
                ...
                end
            begin
            ...
            end
        Begin
        End.

    스택 [AnyProgram | anyFunc | anySubFunc | subSubFunc....

    과 같이 'Topdown' 방식에 알맞게 구성이 되어있고 실제로 모든 변수와
    레이블은 사용하기 전에 선언되어있어야 하며 그 형검사도 엄격히 할
    수가 있읍니다.
    또 프로그램의 구조에 맞게 한 모둘이 한세그먼트를 차지하여 각 모듈
    마다 코드 세그먼트가 틀립니다. 빠르게 컴파일됩니다. 이 방식은 읽는
    동시에 코드를 만들어 내니까요.

    씨의 경우에는 모든 함수와 전역변수가 수평적으로 배열되게 되어 함수
    밖에 어느 곳에나 전역변수와 함수를 정의할 수가 있어 'Topdown' 과
    'Bottomup' 양방식 모두 사용할 수가 있게 됩니다. 보통은 바텀업 방식
    이 주로 사용됩니다. 파스칼과는 달리 씨는 컴파일러를 만드는 이가
    어떤 방식을 사용하던 간에 기본 언어의 정의 ( ANSI 등 )만 충족시키면

    되게되어있고 보통은 바텀업의 방식을 사용하며 그 알고리듬을 위의
    '오토마타' 와 되부름 방식의 혼합형이 주로 사용되는 것으로 알고
    있읍니다.

라. Turing Machine

    'Turing Machine' 이라는 단어의 뜻은 '무한대로 정보의 저장이 가능
    하고, 절대로 고장이 생기지않는 상상의 기계' 라는 뜻으로 제가 어릴
    적에 생각한 바로 그 '컴퓨터' 입니다.

    이 형태는 스택이 아니라 'Tape' 를 사용합니다. 간단한 예를 먼저
    들어본다면, 한 '오토마타'가 있는 데 이 '오토마타'의 역활이 'A'
    와 'B' 의 수를 세어서 그 수가 홀수인가 짝수인가를 검사한다고
    합시다. 그러면

        --------------------------------------------------
                                'AABABBAB'                  'TAPE'
        --------------------------------------------------
                               /\
                               ||
                              HEAD (읽고 쓰기)

    그 'Turing Machine' 은 아래와 같이 정의 됩니다.

             단계 |  A   |   움직임  | 읽기/쓰기  | 결과
            ----------------------------------------------------
               0  |  1   |   오른쪽  |    읽기    |
               1  |  0   |   오른쪽  |    읽기    |

             단계 |  B   |   움직임  | 읽기/쓰기  | 결과
            ----------------------------------------------------
               0  |  1   |   오른쪽  |    읽기    |
               1  |  0   |   오른쪽  |    읽기    |

             단계 |  #   |   움직임  | 읽기/쓰기  | 결과
            ----------------------------------------------------
               0  |  1   |           |            | 참
               1  |  0   |           |            | 거짓

    이 예는 워낙에 간단하기 때문에 오히려 이해가 어려울 수도 있읍니다만

    처음에 들어오는 문자가 'A' 이던 'B' 이던 단게 1 로가며 그 이후에는

    문자가 들어올 때마다 단게를 옮기면서 오른쪽으로 이동하여 새 입력을
    받읍니다 들어온 글자가 짝수이면 단계 0 에 있을 것이고 아니면 1 에
    있게 됩니다.

    아주 간단한 예를 보았읍니다. 위의 예는 DFA 와 거의 같은 행동을 취합

    니다만 각각의 입력에 대한 움직임과 행동을 정할 수 있어 비교가 안될
    정도로 강력한 기능을 발휘합니다. 또 이 '오토마타'는 각 단게에 하위
    'Machine'을 가질 수 있읍니다. 이 오토마타는 긍극적으로 아주 큰 프로

    그램에서 사용될 수 있으며 이 오토마타로 컴파일러를 만든다면 어떤
    언어의 형태이든지 하위 오토 마타의 작성 여부에 따라 컴파일 시킬 수
    있게 됩니다. 즉 위에 설명한 'Top-down' 방식이나 'Finite-state
    Transducers' 는 되부름이나 스택을 이용하여 프로그램을 진행하지만 이

    방식은 실제의 'State Machine'으로 프로그램을 진행하게 된다는 것입
    니다. 아마도 APPLE 컴쪽에는 유저가 자의적으로 'Turing Machine'을
    작성하면 입력된 스트링에 대한 'Turing Machine'의 움직임을 보여주는
    프로그램이 있는가 봅니다. 이 오토마타를 실제로 사용한다면 아마도
    화일 변환이나 그래픽 화면의 특수효과같은 곳에서 사용될 수가 있을
    것입니다. 변수가 많이 사용되고 그 경우의 가지 수와 '인식'된 때의
    행동의 경우가 많고 복잡하게 얽혀있는 경우에는 한 가지씩 분리해서
    작성 할 수 있으므로 효유적이겠읍니다만 글쎄요 책에서 본 예는 3
    개의 문자 'A', 'B', 'C' 를 어떤 입력 스트링에서 그 수가 동일한가
    아닌가를 두 개의 'Tape'를 이용하여 교환하면서 체크하는 'Turing
    Machine' 입니다만 엄청 복잡합니다. 그냥 while = if 문으로 작성하면
    쉬울 것 같은데...
    아마 데이터 베이스 화일의 각 필드를 교환하거나 하는 함수에 응용을
    한다면 빠르고 일관성있게 움직이는 함수가 나올듯도 합니다.

  제목 : 퀵베이직용 외부 라이브러리를 우리 손으로...

  시작하며...

  베이직, 베이직하면 거의 모든 사람들은 한물간 언어니, 초보자들만의 언어니 하며
  말 한다.  물론, 베이직은 초보자에겐 매우 친근하며 배우기 쉬운 언어인 것은
  사실이다.  허나, 베이직하면 거의 모든 사람들은 8Bit Basic 이나 GW-Basic을
  떠올리곤 하는 것이 통념이 되었다.  그러나, 퀵 베이직(Quick-Basic)은 C나
  PASCAL에서 지원하는 것보다 더욱 세심하며 편리한 통합환경을 지원하고 있으며,
  따로 메뉴얼이 필요치 않을 정도의 어드바이스 핼프시스템이란 매우 강력한 자체
  가이드를 내장 사용자의 입장을 최대한 배려하고있다.  모든 것이 그러하듯 처음의
  시작은 힘들다 하지만 처음 프로그래밍언어를 배우려 하는 초보자와 C나 다른
  언어에 실증난 사람들에게 본인은 당당히 퀵을 권하는 바이다.

  라이브러리...

  ’라이브러리‘하면 우리는 보통 C나 Pascal의 한글 라이브러리를 떠올리곤한다.
  물론, 퀵에 비해 그들은 수많은 라이브러리가 개발되 있으며, 지금도 너나할것없이
  개발에 열을 올리는 실정이다.  허나, 퀵은 외부 라이브러리 기능이 있음에도
  불구하고 라이브러리 다운 라이브러리 하나 나오질 않았다.  그러나, 이젠 상황이
  변화되고 있으며, 지금 하이텔 공개 자료실과 동호회 자료실에는 크고 작은, 기능
  또한 타 언어의 라이브러리에 비해 결코 뒤지지 않는, 수는 작지만 하나 둘
  등록되고 있는 실정인 것이다.

  라이브러리를 내손으로...

  그러나 아직도  많은 퀵 사용자들이 라이브러리 생성법을 모르고 있는 듯 하여 이에
  본인은 본지 독자들에게 자신이 만든 프로시져들을 하나의 외부 라이브러리화 하는
  방법을 소개 하고자 한다.  때마침 퀵 연재도 새로 시작 되었고 시기가 좋은 듯
  싶다.

  흔히들 라이브러리하면 베이직이 아닌 다른 언어를 사용, 만들어야 하는 것으로
  알고 있다.  허나, 특별한 경우를 제외 한다면 굳이 다른 언어를 이용할 필요는
  없는 것이다.  그리고 여러 언어를 구사할 수 있는 사용자는 드물다.  이 글에서는
  순수 퀵만을 이용 외부 라이브러리를 만들 것이다.   이해를 돕기위해 간단한 예제
  리스트를 글의 뒷부분에 포함 시켰으니 아래의 설명을 충분히 읽고 직접 하나의
  라이브러리를 만들어 보기 바란다.

  본론으로...

  다들 확장자가 .BAS인 파일은 만들줄 알것이다.  그럼 이것을 컴파일 시키면 .OBJ
  파일과 .EXE 파일이 생김도 알것이다.  우리는 바로 .OBJ 파일을 이용 도스용
  라이브러리(.LIB)와 퀵베이직 통합환경용 라이브러리(.QLB)를 만들게 될 것이다.

  우선, 라이브러리 생성에 필요한 파일들을 동일 디랙토리로 옮겨 준다.  필요한
  파일들은 아래와 같다.

  LIB.EXE    --> 라이브러리 관리자.
  LINK.EXE   --> 파일의 링크 및 통합환경용 라이브러리 생성기.
  BQLB45.LIB --> 통합환경용 라이브러리 생성시 참조 되는 라이브러리 파일.
  QB.LIB     --> 인터럽트 지원용 라이브러리.
  *.OBJ      --> 라이브러리화 될 오브젝트 파일들.

 일단, .OBJ 파일이 만들어져 있다고 가정하고 우선 이것(.OBJ)들을 .LIB 파일로
 만들어 보자.  편의상 새로 만들어질 라이브러리 이름은 new.lib로 가정하겠다.
 그리고 .OBJ 파일 이름들도 편의상 NEW1.OBJ, NEW2.OBJ, NEW3.OBJ로 가정한다.
 그런데, 퀵은 기본적으로 네개의 라이브러를 제공하므로 새로 생성할 라이브러리의
 이름은 기존의 것을 피하기 바란다.

 [예제1]

 C:\>LIB>LIBペ
 ──────────────────────────────────────┐
 Library name: newペ ────────────────────────────┐
 │
 Library does not exist.  Create? (y/n) yペ      ──┐     │       │
 Operations: +new1+new2+new3ペ   ────────────┐   │ │ │
 List file: ペ or new.lstペ ──────────────┐ │ │ │ │
        │       │       │       │       │
 리스트파일을 만들 것인가? ──┘     │       │       │       │
        │       │       │       │
 각각의 .OBJ 파일을 연결        ────┘   │       │       │
        │       │       │
 새로운 라이브러리를 만들 것인가?     ───────┘        │       │
        │       │
 새로만들어질 라이브 파일의 이름입력    ──────────┘     │
        │
 도스 상태에서 lib.exe의 실행    ──────────────┘

  ｢예제1｣에서 보이드시 라이브러리 관리자인 LIB를 도스상에서 실행 시킨다. 그럼
  ｢예제1｣과 같이 차례로 나오는 질문에 해당하는 내용을 입력 하기만 하면
  확장자가 .LIB인 파일이 생성된다.  그럼 생성된 도스용 .LIB 파일을 이용,
  통합환경용의 .QLB 파일을 생성해 보자.

 [예재2]

 C:\>link /q fliename.lib,,nul,bqlb45.libペ
        │       │       │       │
        └───┬─────┘     └───┬────┘
        │       └────── 버젼에 따러 45는 40으로도 가능함.
        │
        └────────── .qlb로 생성하려는 .lib 파일명을 지정하며, 확장자
                             .lib는 생략될 수 없음.  생략될 경우 .OBJ 파일로
                             인식, 지정된 파일이 없을 경우 에러.

  ｢예제2｣에서는 앞의 ｢예제1｣에서 만들어진 .LIB 파일을 이용 .QLB 파일을
  생성하는 명령과 옵션을 이용, 하나의 .QLB 파일을 만드는 과정을 나열한 것이다.
  그런데,  여기서 집고 넘어가야할 일이 있다. .LIB 파일을 이용 .QLB 파일의 생성은
  가능 하나 그와 반대의 일은 불가능 하다.  다시 말해 .LIB 파일을 이용 .QLB
  파일의 생성은 가능하나, .QLB 파일을 이용 .LIB 파일을 생성할 수는 없다는
  점이다.

  위와 같이 하고 DIR을 이용 확인해 보면 확장명만 다른 .QLB 파일 하나가 생성된
  것을 볼 수 있다.  이로써 우리는 하나의 외부 라이브러리를 자신의 손으로 직접
  생성해낸 것이다.  그것도 도스용과 통합환경용 두 가지를...

  허나, ｢예제1｣에서와 같이 오브젝트 파일의 수가 여러개가 아닌 오직 하나가
  존재하며, 이것 하나만을 라이브러리화 하고 싶다면 ｢예제1｣의 Operations:
  질문에 가산기호(+) 하나만을 파일명 앞에 붙여주기만 하면 되는 것이다.  또한,
  도스용 라이브러리가 필요치 않을 경우 ｢예제3｣과 같이 오브젝트 파일을 직접
  통합환경용 .QLB로 생성할 수도 있음을 기억하자.

 [예재3]

 link /q fliename.obj,,nul,bqlb45.libペ
        │       │       │       │
        └───┬─────┘     └───┬───┘
        │       └────── 버젼에 따러 45는 40으로도 가능함.
        │
        └────────── .qlb로 생성하려는 .obj 파일명을 지정하며, 확장자
                         .obj는 생략될 수 있음.

  위와 같이 하면 원하는 .QLB 파일이 생성 된다.  또한 .OBJ 파일들을 +기호로 연결
  하나의 .QLB 파일을 생성할 수도 있다.  그리고 ｢예제2｣의 경우 .LIB 파일
  하나만을 대상으로 삼았으나 이것 역시 가산기호를 이용, 여러개의 도스용 .LIB
  파일을 하나의 .QLB 파일로도 생성이 가능하다.  물론, .LIB 파일과 .LIB 파일의
  연결로 하나의 새로운 .LIB 파일이 생성 될 수도 있다.  그것의 예는 ｢예제4｣와
  같이 하면 된다.

 하나의 복합 라이브를 생성 합니다.

 기존 라이브러리 내용 보기...

  대충 라이브러리 생성 과정은 이것으로 맺고, 다음은 기존의 .LIB 파일에서 .OBJ
  파일을 분리 시키는 방법을 설명 하겠다.  허나, 먼저 라이브러리 파일에 어떤
  오브젝트 파일이 들어 있는지 알아야 가능 하다.   편의상 예로든 .LIB 파일은
  퀵베이직에 포함되 있는 QB.LIB 파일이다.  본 파일의 용도는 위에서 설명 되었다.

 [예제5]

 C:\LIB>LIBペ
 Library name: qb.libペ
 Operations: ペ
 List file: qb.lstペ

 위의 ｢예제5｣와 같이 하면 리스트 파일로 지정한 파일이 생성 된다.  그뒤 리스트
 파일의 내용을 TYPE문이나 스크린 편집기 등으로 QB.LST의 내용을 보면 아래와 같은
 내용이 출력될 것이다.

ABSOLUTE..........absolute          INT86OLD..........int86old
INT86XOLD.........int86old          INTERRUPT.........intrpt
INTERRUPTX........intrpt

absolute          Offset: 00000010H  Code and data size: cH
  ABSOLUTE

intrpt            Offset: 000000e0H  Code and data size: 107H
  INTERRUPT         INTERRUPTX

int86old          Offset: 000002a0H  Code and data size: 11eH
  INT86OLD          INT86XOLD

 위의 내용중 맨위 세줄의 내용은 프로그램에서 호출되는 프로시듀어(대문자)의
 이름과 프로시듀어가 속해있는 오브젝트 파일(소문자)의 이름을 의미 하며, 다음줄은
 오브젝트 파일의 이름과 길이, 그것에 속한 프로시듀어의 이름 등의 정보가 출력
 된다.  허나, 라이브러리 파일에 따라선 오브젝트 파일의 이름도 대문자로 나타날 수
 있다.  그 이유는 [예재1]의 작업시 오브젝트 파일 이름을 소문자로 쓰느냐 대문자로
 쓰느냐에 달려 있다.

  그럼 여기서 QB.LST내용에서 확인한 absolute란 오브젝트 파일을 분리시켜 보자.
  ｢예제6｣과 같이 하면 현 디렉토리에 ABSOLUTE.OBJ란 파일 하나가 나타날 것이다.
  같은 방법으로 intprt와 int86old를 분리 시키시면 된다.  허나, QB.LIB의 내용은
  변동없이 오브젝트 파일을 분리 시키기전과 동일 하다.

 [예재6]

 C:\LIB>LIBペ
 Library name: qb.libペ
 Operations: *absoluteペ
 List file: ペ

  여기서 뭣하러 오브젝트 파일을 분리 시키느냐는 의문이 생길 것이다.  그러나,
  아다시피 통합환경으로 불러 드릴수 있는 .QLB 파일은 오직 하나다. 이러한 이유로
  자신에게 필요한 오브젝트 파일만을 보아 하나의 라이브러리 파일을 생성, 사용할
  수 있게 하기 위함인 것이다.  그러나, 오브젝트 파일의 분리가 번거롭다면
  [예재4]의 내용과 같이 하면 더욱 편리하다.  다음으로 [예재2]의 절차를 거처 .QLB
  파일을 생성 하면 되는 것이다.

  또한 모듈(오브젝트 파일)을 얻은 뒤 얻은 모듈을 .LIB 파일에서 삭제할 수도 있다.

  마무리...

  지금까지 위의 글을 읽으신 독자들께선 베이직 프로시져를 굳이 라이브러리화  할
  필요가 있겠느냐 하는 의문이 생기실 것입니다.  물론, 필요시 INCLUDE, MERGE,
  LOAD 등으로 개발 하려는 프로그램과 합하여 사용 하시면 됩니다.  허나, 프로그램
  작성을 많이 하다보면 자신도 모르게 .OBJ 파일들이 많이 생깁니다. 물론 불필요한
  파일이라면 한번쓰고 지우면 되겠으나, 자신의 프로그램과 자주 연결 사용하게 될
  프로시져 파일들이 있을 것입니다.  바로 이런 파일들을 .LIB 파일로 한대 묶어
  사용 하시면 프로그램 작성때마다  merge니 include 시킬 필요없이 외부
  라이브러리로 이용 하시면 매우 편한 방법이 될것입니다. 물론, .LIB 파일뿐이 아닌
  위의 [예재2]에서와 같이 .QLB  파일로도 생성, 사용이 가능합니다.

DEFINT A-Z
SUB BOX (ZX, ZY, XLen, YLen, BC)

  X1 = ZX * 8: Y1 = ZY * 16
  X2 = (ZX + XLen) * 8: Y2 = (ZY + YLen) * 16
  LINE (X1 - 1, Y1 - 1)-(X2 + 1, Y2 + 1), BC, BF

  LINE (X1 - 1, Y2 + 1)-(X1 - 1, Y1 - 1), 15
  LINE -(X2 + 1, Y1 - 1), 15
  LINE (X1 - 1, Y2 + 1)-(X2 + 1, Y2 + 1), 0
  LINE -(X2 + 1, Y1 - 1), 0

END SUB

SUB BoxWinDow (ZX, ZY, XLen, YLen, BC, CP1, CP2)
  IF CP1 < 1 OR CP1 > 2 THEN CP1 = 1
  IF CP2 < 0 OR CP2 > 1 THEN CP2 = 0
  X1 = ZX * 8: Y1 = ZY * 16
  X2 = (ZX + XLen + 2) * 8: Y2 = (ZY + YLen + 2) * 16
  IF CP2 = 1 THEN LINE (X1 + 4, Y1 + 4)-(X2 + 4, Y2 + 4), 8, BF
  LINE (X1 + 8, Y1 + 8)-(X2 - 8, Y2 - 8), BC, BF

  IF CP1 = 1 THEN
     '좌상 선 및 색칠
     LINE (X1, Y2)-(X1, Y1), 10
     LINE -(X2, Y1), 10
     LINE -(X2 - 7, Y1 + 8), 10
     LINE -(X1 + 7, Y1 + 8), 10
     LINE -(X1 + 7, Y2 - 8), 10
     LINE -(X1, Y2), 10
     PAINT (X2 - 7, Y1 + 4), 10
     PAINT (X1 + 4, Y1 + 4), 10
     PAINT (X1 + 4, Y2 - 8), 10
     '우하 선 및 색칠
     LINE (X1, Y2)-(X2, Y2), 2
     LINE -(X2, Y1), 2
     LINE -(X2 - 7, Y1 + 8), 2
     LINE -(X2 - 7, Y2 - 8), 2
     LINE -(X1 + 7, Y2 - 8), 2
     LINE -(X1, Y2), 2
     PAINT (X1 + 7, Y2 - 4), 2
     PAINT (X2 - 4, Y2 - 4), 2
     PAINT (X2 - 4, Y1 + 8), 2

     LINE (X1, Y1)-(X1 + 7, Y1 + 8), 2
     LINE (X2, Y2)-(X2 - 7, Y2 - 8), 10

  ELSEIF CP1 = 2 THEN
     '외각 박스 및 색칠
     LINE (X1, Y1)-(X2, Y2), 7, B
     LINE (X1 + 7, Y1 + 8)-(X2 - 7, Y2 - 8), 7, B
     PAINT (X1 + 4, Y1 + 4), 7
     PAINT (X2 - 4, Y1 + 4), 7
     PAINT (X2 - 4, Y2 - 4), 7
     PAINT (X1 + 4, Y2 - 4), 7
  END IF

  '내부선 좌상
  LINE (X1 + 6, Y2 - 8)-(X1 + 7, Y1 + 8), 0, BF
  LINE (X1 + 6, Y1 + 7)-(X2 - 6, Y1 + 8), 0, BF

  '내부선 우하
  LINE (X1 + 8, Y2 - 7)-(X2 - 7, Y2 - 8), 15, BF
  LINE (X2 - 7, Y2 - 7)-(X2 - 6, Y1 + 8), 15, BF

  '외각선 출력
  LINE (X1, Y2)-(X1, Y1), 15
  LINE -(X2, Y1), 15
  LINE (X1, Y2)-(X2, Y2), 0
  LINE -(X2, Y1), 0
END SUB

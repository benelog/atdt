

 한재룡   (nuisance)
한글 입력 오토마타의 작성                    11/25 05:27   495 line


  안녕하십니까.

  이 화일은 이전의 화일의 연속으로 한글 입력의 특성을 살펴보고 DFA 를
  사용하여 입력 루틴을 만들어 보겠읍니다.

  여기에서 사용되는 코드와 자판은 조합형과 2 벌식 자판입니다.

3. 한글 입력의 특성

  한글을 나타내는 방식은 2 바이트로서 1 글자를 나타내며, 2 바이트에는
  초성, 중성, 종성이 각각 5 비트씩 들어있고 최상위 한 비트는 한글임을
  나타내는 비트로서 사용됩니다.

           |  제 1 바이트  |  제 2 바이트  |
           | | | | | | | | | | | | | | | | |
           ---------------------------------
             |         |         |         |
             |         |         |         |
      프레그 |  초성   |  중성   |  종성   |

  각 5 비트로 정의 되어있고 제 1 바이트가 상위바이트가 됩니다.그러므로
  0 - 31 이 각 부분이 가질 수있는 최대값이 됩니다. 5비트에 대한 코드는
  여러가지가 있고 가장 많이 사용되는 것이 조합형과 완성형입니다.
  완성형은 사용하기에 문제가 많은 것같아 여기서는 조합형의 코드를
  살펴보겠읍니다.

  위에서 빈칸은 Fill Code 로서 사용되지 않읍니다. 씨에서는 스트링의
  끝을 0 으로 알아내므로 만일 종성이 0 이고 중성도 하위 바이트에 0 의
  값을 준다면 씨에서는 스트링의 끝으로 계산되기 슆읍니다. 이럴경우에는

  쓰이지않는 Fill Code 로서 영문의 스페이스 처리를 해주면 편합니다.
  보통 가장 하위에 쓰이지 않는 비트 ( 초성 1, 중성 2, 종성 1 ) 을

      1 00001 00   010 00001 --> 0x8441 이 됩니다.

  씨에서 한글을 편하게 다루려면 각 5 비트에 해당하는 구조체를 사용하면
  좋읍니다.

      typedef union {
              unsigned char high, low;
              struct {
                  unsigned char  종성 : 5;
                  unsigned char  중성 : 5;
                  unsigned char  초성 : 5;
                  unsigned char  flag : 1;

              } h;
              unsigned int code;
      } 한글코드;

  이라고 선언하시면 됩니다. 여기서 생각할 점은 스트럭처 안에 선언된
  부분입니다. 각 5 비트로 되어있고 unsigned char 형으로 선언하였는데
  만일 char로 선언하게 되면 5 비트중의 최상위 비트가 세트되어 있으면
  음수로 돌려주게됩니다. 만일 17 이란 값이 5비트에 들어있게 되면 10001
  인데 이것을 컴파이러가 10000001을 char 로 해석하여 -127 을 돌려주게
  되니 주의하십시요. 그리고 만일 han.h.종성 이라고 쓰면 이 변수의
  크기는 8 비트입니다. 5 비트로 해석되는 것은 이 변수에 다른 값을 할당
  하거나 이 변수로부터 할당받을 때입니다. 큰 차이가 없는 말 같으나
  가끔은 햇갈릴 때가 있읍니다.
  여기서 보면 한 바이트의 변수를 '초성', '중성' 등에 사용하면 사용되지
  않는 3 비트가 있음을 알게 됩니다. 아래의 '오토마타'에서는 이 3비트를
  아주 중요하게 사용하여 필요없는 테이블의 선언을 줄였읍니다.
  이제 한글 코드의 특성을 살펴보시겠읍니다.

 가. 입력의 종류

   한글 입력은 한글자를 만들기 위해서 최소 1 번의 키입력부터 최대 5 번
   의 키 입력이 이루어지게 됩니다. 입력되는 형태는 일반아스키 문자이며
   이 아스키 문자를 자판의 배열에 따라 한글 문자로 변형을 해야 합니다.
   즉 'A' 를 누르면 'ㅁ' 을 입력한것으로 해석을 해야하므로 이 변환을

   빠르게 하기위해서 'A''B''C'....'X','Z' 만큼의 배열을 선언하여 이
   배열에다가 'A' -> 8 과 같이 해당하는 한글 코드를 넣어둡니다. 그러나
   한글에는 'ㄲ', 'ㅆ','ㅒ' 와 같은 자판도 있으므로 이 들을 구별하
기
   위해서는 영문에서 사용하는 캡롹이 아니고 쉬프트키의 상태를 검사하여

   만일 쉬프트키가 눌렸으면 유저가 '확장 자판'을 이용한다는 것으로
   간주하게 됩니다 이 자판을 위해서도 또 거금 '26 바이트'가 테이블로
   사용됩니다.

   이 두 배열에 들어간 값은 '초성' 의 코드입니다. 위의 코드표를 보시면
   아시겠지만 같은 자음이라도 초성과 종성의 코드가 틀리고 초성에는
   사용되면서 종성에는 사용되지 않는 것이 3 개( ㅆ, ㅉ, ㅃ ) 가 있
고
   종성에 사용되는 복 자음 거의가 초성에는 사용되지 않음을 알 수 있읍
   니다. 위의 두 배열에는 초성에 해당하는 코드가 들어가 있고 이 코드를
   주로 사용하게 되지만 종성의 코드를 참조하기 위해서 키보드로 입력할
   수 있는 모든 자음의 코드에 해당되는 종성의 배열을 선언하게 됩니다.

      종성 테이블[] = {

          0,  ---> 해당코드가 없다
          1,  ---> Fill Code
          2,  ---> 초성 ㄱ 의 코드 2 로 이 배열을 참조하면 종성 2 이다

          3,  ---> 'ㄲ'
          5,  ---> 초성 ㄴ 의 코드 4 로 ----> 종성 ㄴ 의 코드 5

   와 같이 사용되게 됩니다. 그런데 위의 배열만으로는 종성에만있는
   복자음 'ㄹㄱ', 'ㄹㅅ' 등 키보드를 두번 눌러 입력하게 되는 받
침은
   사용할 수 없게됩니다. 이들 복합자음 받침을 위하여 또 하나의 배열을
   선언하게됩니다

      복 자음 바침[11][3] = {

      { 2, 11, 4 }, ---> 'ㄱ' 과 'ㅅ' 이 합쳐서 'ㄱㅅ' 을 만든다

      { 4, 14, 6 }, ---> 'ㄴ' 과 'ㅈ' 이 합쳐서 'ㄴㅈ' 을 만든다
.
       ...

  위와 같이 선언하면 받침을 입력받는 단게에서는 복합 받침이 되는가를
  우선 검색한다음에 해당하는 복자음이 있으면 화면에 그려주게 되고
  없다면 다음 글자의 입력으로 간주하게 됩니다. 그러므로 2 벌식에서는
  다음 문자로 연결되는 부분에서 한 번 키보드를 잘 못 누르면 2 글자를
  못 쓰게 됩니다.

  위의 테이블에 이제 복모음의 조합을 복자음 사용하듯이 선언하면 일단은
  문자에 대한 선언은 모두 끝나게 되고 그 테이블들을 이용하여 영문
  아스키 값을 돌려주는 IBM 컴에서 구박받는 '우리 한글' 을 프로그램내
  에서 소프트 웨어적으로 문자 코드를 만들어낼 준비가 되었읍니다.
  이제는 한글이 조합되는 과정을 살펴 보겠읍니다.

나. 입력 데이터의 특성

   물론 한글에는 뚜렸한 특성중에서도 '자', '모' 로 이루어진다는 점이
   가장 특색있는 점일 것 입니다. 한글 키 입력은 우선 '자', '모' 로
   대별할 수가 있읍니다. 그러나 '초성' 과 '종성' 의 구별을 항상 해야
   하므로 '자', '모' 의 구별만으로 프로그램을 짜기에는 너무 정보가
   부족합니다. 그래서 입력데이터의 정보를 4 가지로 늘려보았읍니다.

      1. 자음                      0x00
      2. 모음                      0x20
      3. 복(자, 모)음 구성 가능 ?  0x40  ----> ㄴ, .,ㅡ
      4. 오직 초성에만 ?           0x80  ----> ㅆ, ㅉ, ㅃ

  이 정보들은 한글 문자코드의 사용되지 않는 3 비트에 넣어 쓰게 됩니다

  그러면 한글을 구성하기 위한 입력의 구성을 살펴보십시다.

  아래에서 '두모' 와 '두자' 는 복합으로 사용될 수 있는 첫 모음과 자음
  을 나타냅니다. 그리고 '모' 와 '자' 는 위의 문자들을 포함한 개념입니
  다. 또 !자 라고 쓴 것은 ㄸ, ㅉ, ㅃ 등 받침으로는 사용될 수 없는
 자음
  에대한 개념입니다. !자 라고 구별할 필요가 꼭 있는 것은 아닙니다만
  약간이라도 빠르고 작게 짜기위한 욕심입니다.

      1. 자 + 모
      2. 자 + 모 + (자 - !자)
      3. 자 + 두모 + 모 + (자 - !자)
      4. 자 + 두모 + 모 + 두자 + (자 - !자)

      5. 모   ---> 이들은 앞뒤의 문자들과 어울려 글자를 형성할 수 없을
      6. 자   경우에 따로 떨어진 문자가 되며 [ㅞㄴ] 과 같이 될 수도 있다


4. 한글 입력 오토마타의 작성

  입력 데이터의 특성을 구분했고 출력되는 데이터의 특성도 검사했읍니다
  보통 DFA 는 입력을 읽어들여 결과를 리턴하는 단방향의 구조일 경우가
  많지만 한글 입력 오토마타는 읽는 동시에 2 바이트의 한글 코드에 그
  입력 결과를 즉시 돌려주면서 출력함수와 밀접하게 돌아가야 하므로 조금
  복잡해지는 의미가 있읍니다. 그리고 입력의 수준을 만족한 상태에서도
  계속해서 오류의 입력이 이루어질 때까지 입력을 받게 됩니다. 이런
  알고리듬을 'Greedy Automata'라고 하며, 예를 들어 '짧'이라는 입력이
  있었다면 이미 한 글자를 이루기에 충분한 입력이 이루어져있지만 다음의
  키를 기다려 새로운 글자의 조합을 예정합니다. 이 부분이 아마도 한글
  입력 오토마타를 작성하는 데에 있어서 가장 큰 문제일 것입니다.
  편하게 하려면 이 부분만을 새로운 하위 오토마타의 개념으로
   '자 + 모 + 자' 가 형성된 상태에서 사용한다면 코드가 '깨끗'해지겠읍
  니다만 한글 입력 오토마타 처럼 작은 루틴에는 과분한 대우가 되겠지요

  여기서 DFA 의 스테이트 머쉰을 짜 보겠읍니다. 입력되는 데이터는 위에
  정의한  5 가지의 정보입니다. 제 6 단계를 하나 더 쓰면 보기에는 편하
  겠읍니다.

 단게   |    자      모      두모       두자     !종성 |
=================================================================
                                                       |
   0    |    1        2        3         1        1    | 시작단게
   1    |    끝       2        3         끝       끝   | 초성
   2    |    4        끝       끝         5       끝   | 단 중성
   3    |    4        찾기     찾기       5       끝   | 복 중성 가능
   4    |    끝       끌기     끌기      끝       끝   | 단 초성
   5    |    찾기     끌기     끌기      찾기     끝   | 복 종성 가능

  위에 있는 'Finite State' 테이블이 바로 DFA 의 스테이트 테이블입니다.
 '끌기' 라고 쓰인 부분은 앞의 종성으로 쓰여진 자음을 다음 문자의 초성
  으로 끌어간다 뜻입니다. 제 6 단계로 '복종성 완성' 단계를 정의한다면
  좀 더 이론적이 되겠읍니다.

  이 머쉰을 돌리는 드라이버에서는 항상 이전단게를 기억했다가 그 다음
  단계에 맞는 행동을 취하게 됩니다. 그래서 아래의 소스를 보시면 아시
  겠지만 보통의 한글 입력 루틴과는 달리 숫자의 크기나 상태를 검사하는
  비트연산이 거의 없음을 아실 수가 있으실 것입니다. 이제는 코드를
  짜기만 하면 됩니다.
  코드를 작성하실 때에는 이 '오토마타'가 가능하면 별개의 단위로 작성
  되어야 여러 다른 프로그램에 쉽게 이식이 될 것입니다. 아래의 루틴을
  충분히 이해하시게되면 아마도  2 벌식 자판, 조합형에서 다른 프로그램
  을 짜기위해, 아니면 버전 업을 하기 위해 '한글 입력 오토마타'를 다시
  고쳐쓰는 일은 없을 것이라고 생각합니다.

  아래의 오토마타에서 주의 깊게 보실 부분은 두 군데에서 자체로 되부름
  을 하며, 만일 '삸' 이라는 문자가 작성된 상테에서 'ㅏ' 가 들어오면

  '살사'라는 문자열이 되어야 하는데 이 부분은 이 전에 함수가 불렸을
  때에 주어진 문자를 기억하고, 또 이전의 단계를 기억하며 위에있는
  복종성 테이블을 사용하여 그런데로 간단히 해결을 합니다.

  아래의 루틴을 사용하시게 되면 전역으로 선언된 두 변수 currCode,
  prevCode 에 주의 하셔야 합니다. 만일 루틴이 1 을 리턴하면 지금 입력
  된 문자로 인해 두 문자가 생성됐음을 알립니다, 앞 문자는 prevCode 에
  있고 지금 다루는 문자는 currCode 에 있게 됩니다. 그리고 영문등을
  토글하실 때에는 새로 한글을 입력받으려고 호출하기전에 machine(0) 와
  같이 초기화 시켜서 기억된 이전의 상태를 반드시 지우셔야 합니다.
  이런점은 이 오토마타에 특별히 해당되는 것은 아닙니다. 그럼 예로
  아래의 함수를 사용하는 코드 조각을 써본다면

      if( isalpha( ch ) && HANGLE_MODE )
      {
          /* 위에 있는 토글 키를 받는 부분에서 machine(0) 를 호출 */

          if( bioskey(2) & 3 )  ch = STable[ toupper(ch) - 'A' ];
          else                  ch = NTable[ toupper(ch) - 'A' ];

          if( machine( ch ) )
          {
              *(int *)str++ = (int)prevCode.code;
              putHch( prevCode.code );
              advenceCursor(2);
          }
          putAtCursor( currCode.code );
      }
      else
      {
          if( !doControl( ch ) )
          {
              *str++ = ch;
              putEch( ch );
              advenceCursor(1);
          }
          machine( 0 );   // 리셋
      }

  과 같이 사용하시면 됩니다. 제가 입출력 라이브러리 함수가 없어서 거의
  몸으로 디버깅을 했기 때문에  약간 자신이 없읍니다만 만일 문제가
  있더라도 아마 변수의 초기화 문제 등일 것입니다. 한글 코드의 필코드를
  현재의 출력루틴이 0 으로 잡고 있다면 아래의 오토마타에 화면 출력이
  정확히 안돌아갈 수 도 있는데 그것은 변수의 초기화 과정을 손보시거나
  하시면 됩니다. 아마 큰 문제는 없을 것으로 압니다. 문제가 있다면 꼭
  알려주시기 바랍니다. 충분한 설명이 되었을줄로 믿고 아래의 루틴에 써
  있던 도쿠먼트는 생략했읍니다.

/* Defines ----------------------------------------------------------
*/

#define     NO_NEXT         7
#define     TRAIL           8
#define     FIND            9
#define     OC              0x80    // Only ChoSung 'dd', 'bb', 'zz'
#define     DU              0x40    // Able to construct double factor
#define     MO              0x20    // Vowel
#define     JA              0x00    // Consonant

/*  Type definitions -------------------------------------------------
*/


typedef union {

      word    code;
      struct
      {
          byte    low;
          byte    high;
      } b;
      struct
      {
          byte    jong    : 5;
          byte    jung    : 5;
          byte    cho     : 5;
          byte    flag    : 1;
      } h;

} HAN_CODE;

//  Global Variables ----------------------------------------------

static  HAN_CODE    currCode = 0x8441;
static  HAN_CODE    prevCode = 0x8441;

static byte NTable[] =
{
//  A               B               C               D
//---------------------------------------------------------------
    8  | JA,        26 | MO,        16 | JA,        13 | JA,
//  E               F               G               H
//---------------------------------------------------------------
    5  | JA | DU,   7  | JA | DU,   20 | JA,        13 | MO | DU,
//  I               J               K               L
//---------------------------------------------------------------
    05 | MO,        7  | MO,        3  | MO,        29 | MO,
//  M               N               O               P
//---------------------------------------------------------------
    27 | MO | DU,   20 | MO | DU,   4  | MO,        10 | MO,
//  Q               R               S               T
//---------------------------------------------------------------
    9  | JA | DU,   2  | JA | DU,   4  | JA | DU,   11 | JA,
//  U               V               W               X
//---------------------------------------------------------------
    11 | MO,        19 | JA,        14 | JA,        18 | JA,
//  Y               Z
//---------------------------
    19 | MO,        17 | JA
};

static byte STable[] =     /* Shift + key table */
{
//  A               B               C               D
//----------------------------------------------------------------
    8  | JA,        26 | MO,        16 | JA,        13 | JA,
//  E               F               G               H
//----------------------------------------------------------------
    6 | JA | OC,    7  | JA | DU,   20 | JA,        13 | MO | DU,
//  I               J               K               L
//----------------------------------------------------------------
    05 | MO,        7  | MO,        3  | MO,        29 | MO,
//  M               N               O               P
//----------------------------------------------------------------
    27 | MO | DU,   20 | MO | DU,   6  | MO,        12 | MO,
//  Q               R               S               T
//----------------------------------------------------------------
    10 | JA | OC,   3  | JA,        4  | JA | DU,   12 | JA,
//  U               V               W               X
//----------------------------------------------------------------
    11 | MO,        19 | JA,        15 | JA | OC,   18 | JA,
//  Y               Z
//---------------------------
    19 | MO,        17 | JA
};

static byte Cho2Jong[21] =
{
   0,  1,  2,  3,  5,  8,  1,  9, 17, 19,  1,
  21, 22, 23, 24,  1, 25, 26, 27, 28, 29
};

static byte CombJung[7][3] =
{
  { 13,  3, 14 }, { 13,  4, 15 }, { 13, 29, 18 },
  { 20,  7, 21 }, { 20, 10, 22 }, { 20, 29, 23 },
  { 27, 29, 28 }
};

static byte CombJong[11][3] =
{
  {  2, 11,  4 }, {  4, 14,  6 }, {  4, 20,  7 },
  {  7,  2, 10 }, {  7,  8, 11 }, {  7,  9, 12 },
  {  7, 11, 13 }, {  7, 18, 14 }, {  7, 19, 15 },
  {  7, 20, 16 }, {  9, 11, 20 }
};

static byte NextState[6][5] =
{
// State    ||      JA        MO        JA|DU     MO|DU    JA|OC
//-------------------------------------------------------------------
/* Start 0  */   { 1,        2,        1,        3,        1,      },
/* Cho   1  */   { NO_NEXT,  2,        NO_NEXT,  3,        NO_NEXT },
/* Jung  2  */   { 4,        NO_NEXT,  5,        NO_NEXT,  NO_NEXT },
/* DJung 3  */   { 4,        FIND,     5,        FIND,     NO_NEXT },
/* Jong  4  */   { NO_NEXT,  TRAIL,    NO_NEXT,  TRAIL,    NO_NEXT },
/* DJong 5  */   { FIND,     TRAIL,    FIND,     TRAIL,    NO_NEXT },
};

static int findCombination( int old, int new )
{
  byte    (* comb)[3];
  int     max;

  if( old & MO )  max = 7,  comb = CombJung;
  else            max = 13, comb = CombJong;
  for( ; max > 0; comb++, max-- )
      if( (*comb)[0] == (old & 0x1F) && (*comb)[1] == (new  & 0x1F) )
          return (*comb)[2];
  return 0;
}

static int combJong2Jong( int combJong )
{
  byte    (* comb)[3] = CombJong;
  int     max = 11;

  for( ; max > 0; comb++, max-- )
      if( (*comb)[2] == combJong ) return (*comb)[0];
  return 0;
}

int machine( int newChar )
{
  static int  newState, oldState, oldChar;
  int         find;

  if( newChar == 0 )
  {
      newState = oldState = oldChar = 0;
      prevCode.code = currCode.code = 0x8441;
      return 0;
  }
  if( oldState > 5  ) oldState = 0;
  newState =  NextState[oldState][ newChar >> 5 ];
  switch( newState )
  {
      case    1    :  currCode.h.cho  = newChar ;  break;
      case    2    :
      case    3    :  currCode.h.jung = newChar ;  break;
      case    4    :
      case    5    :  currCode.h.jong = Cho2Jong[newChar & 0x1F];
                                                    break;
      case NO_NEXT :  newState = 0;                 break;
      case TRAIL   :
          if( oldState == 5 )
          {
                  find = combJong2Jong(currCode.h.jong);
                  find = find ? Cho2Jong[find] : 1;
          }
          else    find = 1;
          currCode.h.jong = find;     prevCode = currCode;
          currCode.code   = 0x8441;
          currCode.h.cho  = oldChar;  oldState = 1;
          machine( newChar );
          return 1;
      case FIND    :
          find = findCombination( oldChar, newChar );
          if( find )
          {
              if(oldState == 3) currCode.h.jung = find, newState = 3;
              else              currCode.h.jong = find, newState = 5;
          }
          else    newState = 0;
  }
  if( newState == 0 )
  {
      prevCode = currCode;  currCode.code = 0x8441;  oldState = 0;
      machine( newChar );
      return 1;
  }
  oldState = newState;  oldChar = newChar;
  return 0;
}
